# 理财产品每日收益看板

## 字体字号字重规范（2026-11-19 定稿）

改动样式时遵循以下固定阶梯，勿再新增 0.5px 相邻档位（维护约定，详见字体盘点审核稿）。

### 字号阶梯
| 端 | 档位 | 用途 |
|---|---|---|
| 桌面 | 11 / 12 / 13 / 15 / 21 / 36 | 说明副行 / 表头卡片 / 表格正文 / 强调大数 / 区块标题·指标值 / 主标题 |
| 手机竖屏 | 11 / 12 / 12.5 / 17 / 21 | 说明·年月表 / 表头控件 / 表格正文 / 区块标题·指标值 / 主标题 |
| 手机横屏 | 11.5 / 12 / 13 | 表格正文·表头·说明 / 日历主数值 / 强调 |

犄角上标（如 T+N 角标 sup.nav-lag）保持 9px，属于唯一例外。

### 字重（4 档固定）
- 400：正文、说明
- 600：表头、次级标题
- 700：数值强调、可排序列
- 800：仅主标题

### 颜色与字体
- 辅助/说明文字统一用 `var(--muted)`（#5d6b76，5.48:1，达 WCAG AA），不再新增更浅的灰。
- 中文一律 `var(--font)`，数字/代码一律 `var(--mono)`；移除 Arial 与混排声明（★ 符号按钮除外）。

> 注：本规范已同步进 `PROJECT_NOTES.md`（第 8 节）并登记到守卫清单 protected，两端改动样式时都须遵守。

### 字号专用档（2026-11-20 审核稿 B1 登记）
固定阶梯之外的**已登记专用档**，不得随意扩散：
- 桌面：指标卡主值 26px；日历中 16px 为控件继承字号，不直接渲染正文。
- 手机竖屏：指标卡主值 15px、3 列卡副行 10.5px、单位「元」9.5px；≤340px 副行 9px / 数值 10px。
- 手机横屏：指标卡主值 15px、副行 10px、单位 9.5px。
- h1 按断点固定整数：桌面 36px / 手机竖屏 21px / 横屏 27px（禁止 vw clamp 产生小数，B4）。
- 11.5px（说明文字）与 12.5px（控件）为**冻结例外**（B2）：允许现存用法，不得新增；全局替换会导致手机指标副行「+0.43%」重新换行。

### 表格行高分层（2026-11-20 审核稿 A1 登记）
桌面四表表头统一 40px；数据行按内容分层，**不强行等化**：

| 层级 | 行高 | 适用 |
|---|---|---|
| 密集双行 | 26px | 首页盈亏汇总（一个产品占主行+数据行两行） |
| 按钮单行 | 35px | 交易页持仓汇总（带加购/赎回/清仓按钮） |
| 分组流水 | 32px | 交易页交易流水（月份组行与明细行同高） |
| 双行数值 | 40px | 产品库（净值/成立日等两行数值块） |

手机竖屏（A4）：表头统一 38px；数据行三档——**盈亏汇总主行+数据行 35px**（2026-11-20 再压缩，原 38px，td 上下 padding 5→4px）、持仓汇总/交易流水明细 38px、双行 48px（交易流水月份组/产品库）。长名称自然换行行由内容撑高（如持仓汇总约 48.25px），不被裁切；左右 padding 不动以免影响列宽；字号/千分位/列宽/评分列均不缩（方案 C 2026-11-20，由 44/56 收紧而来）。实测 393×852：盈亏汇总 30 行全部 35px、无单元格内容裁切、无横向溢出。

**手机端持仓汇总操作按钮（2026-11-20）**：`#sum-table tbody td:last-child .mini` 用 `padding:2px 6px;line-height:1.2`（与交易流水/产品库按钮同款），实测由 44×26px 收到 38×20.4px，贴合 12px 文字，不再过宽过高；桌面端仍为 `2px 7px`。

**例外（A5）**：手机横屏表头因两行文字实测 42.4px，登记为唯一高于桌面 40px 的例外，不再继续压缩。横屏数据行沿用独立媒体查询（约 32px），不受方案 C 竖屏改动影响。

### 页内导航（方案 E 2026-11-20，分页版）
手机竖屏下，首页顶部跳转条把页面分成 3 个子页（盈亏汇总／盈亏日历／盈亏趋势），交易页同样有跳转条分成 2 个子页（持仓汇总／交易流水）；点标签只显示对应子页（`.subpage-off{display:none}`，桌面端/横屏不隐藏、仍全部纵向排列），切换后回页顶并触发 `window resize` 让趋势图 ECharts 重新取尺寸。跳转条高亮色与主标签统一（`#e6f2f6` 底 / `accent-deep` 字）。主标签（首页/交易/产品）手机端行高压到 36px（padding 5px 14px）。右下角「返回顶部」改为 30px 无填充向上箭头 SVG（去文字/去深底色），首页下滑超过约 420px 出现、点击回页首。产品页不受影响。

**两行导航融合（2026-11-20）**：手机竖屏下，首页/交易的主标签与子页条拼成一张卡——主标签加 `.has-sub`（页签切换 JS 按当前页是否有子页条切换该类），去底圆角/下边框/下间距，子页条去上圆角改虚线顶边、紧贴无缝；行高进一步压缩（子页按钮 padding 4px 2px）。产品页无子页条，主标签保持全圆角。横屏/桌面不触发（媒体查询 max-width:760px）。

### 表单弹窗（手机 2026-11-20）
- 新增交易：去掉底部文字说明（`.note-line{display:none}`），压缩字段间距与控件高度（field margin 6px、控件 min-height 34px），手机一屏录入无需滑动。**2026-11-20 手机端表单改两列**：交易类型与确认日期加 `.field-wide` 跨整行，申购日期与申购金额并列、份额与成交净值并列（`#modal-trade .form-grid{grid-template-columns:repeat(2,minmax(0,1fr))}`）。
- 添加产品：标题区顶部留白（padding-top 14px）、按钮行留 5px 呼吸间距；「一键识别填入」改浅蓝底（`#e6f2f6` / `accent-deep` 字，与上传按钮协调）；登记编码标签由「登记编码（选填，留空按名称自动匹配）」缩短为「登记编码（选填）」（说明移入 placeholder），解决两列布局下标签换行导致的输入框不对齐。**2026-11-20 去掉 OCR 下方的常驻说明文字**（原 `.ai-strip-tip`「本地识别，不联网、不用密钥、永久免费…」），识别结果提示仍由 `aiMsg()` 按需给出。
- 本地 OCR 识别超时保护 60→150 秒（手机首次加载中文 wasm 模型较慢，降低误判），超时提示改为引导重试/手工填写。
- **聚焦不自动放大（2026-11-20 修复，全站）**：iOS Safari 只要聚焦的字号 <16px 就会强制放大整页（表现为点文本框后弹窗被推到右侧、按钮被截出屏幕）。根因是手机端为压高度写的 13px 规则（含 iOS 专属分支）覆盖了 16px。现统一在 `@media (max-width:760px)` 内用 `.modal-card input:not([type=hidden]):not([type=file]),.modal-card select{font-size:16px !important;-webkit-text-size-adjust:100%}` 抬回字号，高度/间距仍靠 `min-height`/`padding` 压缩，不再覆写小字号；删除 `#modal-trade` 与矮屏 `#modal-add` 的 iOS 13px 规则。**进一步全站化**：手机端所有文本类 `input`/`textarea`（产品搜索、筛选搜索、各弹窗输入框）统一 `font-size:16px !important`；`select` 不触发 iOS 缩放、复选框/文件框排除，表头下拉字号不受影响。
- **底部按钮两列对齐与防误触（2026-11-20）**：`.modal-foot` 由 `flex:1` 改为 `display:grid;grid-template-columns:repeat(2,minmax(0,1fr))`，取消/提交（或取消/保存）严格等宽对齐；新增交易 `.modal-body` 底部加 20px padding，确认日期与按钮区之间留呼吸区，避免手指误触提交。iPhone 393×852 实测：所有控件 16px、按钮 176/176 等宽、日期面板在屏内、`visualViewport.scale=1`、`scrollWidth=393` 无横向溢出。

**最近添加记录（2026-11-20，手机/桌面一致）**：添加产品弹窗底部的「最近添加记录」去掉登记编号（`AF…`）与代销机构（建设银行），改为「名称 + 日期时间 + 右侧『修改 / 删除』小按钮」。渲染按 `at` 倒序（保存后本地已 `unshift` 到首行，刷新后云端同样按时间倒序，两处顺序一致）。「修改」带原记录值打开弹窗（标题变「修改产品」），保存时用同一 id 走 `addProduct` 的 key upsert 覆盖更新（并跳过重复编码拦截）；「删除」调 `STORE.removeProduct(id)` 从云端产品库移除。

**返回顶部按钮（2026-11-20 全站应用）**：悬浮按钮从仅首页手机端扩展到首页/交易/产品三个页签、手机与桌面端——CSS 基础样式放到文件头部（桌面 right16/bottom20、34px、带阴影；手机贴安全区、30px），`syncTopBtn()` 不再判断 `activeTab()==='hold'`，只按 `pageYOffset > 420` 显示。

**产品名联动与清除筛选（2026-11-20）**：点盈亏汇总/持仓汇总里的产品名（`data-goto-trade`）切到交易页并按该产品过滤持仓汇总与交易流水。持仓汇总页在筛选态显示提示条 `#sum-filter`（与交易流水 `#trade-filter` 同款 `.active-filter` 样式），含「清除筛选」按钮；清除逻辑抽为 `clearTradeFilters()`，两个清除按钮共用——清空 `flowState.pid` 并恢复全局产品全选。无筛选时提示条隐藏。

**交易流水默认展开规则（2026-11-20）**：交易页首次加载不再自动把年月筛选定位到最近交易月，`flowState.year/month` 默认为空 → 列出全部有流水的月份分组。月份展开状态 `flowOpenMonths` 默认只展开最新月（`months[0]`，已按降序），其余月份折叠只显示「共 N 笔」汇总；人工点击过的月份写显式 `true/false` 优先尊重。点月份行按当前实际 `open` 类取反（`!mh.classList.contains('open')`），避免折叠月（状态为 undefined）点不开。产品联动 `filterFlowByProduct()` 会清空 `flowOpenMonths` 回到该默认规则。桌面/手机一致。

**手机横屏表格微调（2026-11-20）**：盈亏汇总序号列 26→32px 让「序号」二字不换行，从产品名列匀出 6px（总宽不变）；竖屏/桌面不受影响。产品库筛选栏「新品」按钮移入 `.filter-tail` 首位（横屏第二行首位、竖屏与收藏同行）；「成立年化」列改为「成立至今」，单元格与 30日列同构双行——上日均万收（年化 ÷3.65 反算）、下成立年化，`sinceCell()` 生成，`data-sort="ann"` 排序口径不变。

**OCR 识别提速（2026-11-20）**：打开「添加产品」弹窗即后台预热 Tesseract worker（`warmupOcr()`），把 3.8MB wasm + 1.7MB 中文语言包的下载/编译耗时（手机可达数十秒）藏进用户选图/填表时间，点识别只剩 recognize（本机实测约 1 秒）；进度回调 `ocrProgressCb` 与 worker 创建解耦，预热后仍能显示识别进度。上传图长边压缩 1600→1280px（面积少 36%，产品详情页字号大、识别率不受影响）。预热失败静默，不影响正式识别重试。

**弹窗背景锁定（2026-11-20）**：添加产品/新增交易/确认框打开时锁住背景页滚动——`bindModalScrollLock()` 用 MutationObserver 监听三个 modal 的 hidden 变化，任一打开即记 scrollY 并给 body 加 `.modal-lock`（fixed+负 top，防 iOS Safari 滚动穿透），全部关闭再恢复原位；覆盖关闭按钮、点遮罩、提交成功、取消所有路径。
